# Phase 3：证据分析

**目标**：把原始来源变成有置信度标注的结论——每个结论标明有多可靠、基于几个独立来源、有没有矛盾。

**核心原则**：10 篇文章说同一件事不等于 10 重证据——可能都在转述同一篇论文。两篇文章说法矛盾不等于"观点不一"——可能一篇用的是 2019 年数据另一篇用 2024 年的。你的工作是数出真正独立的来源有几个，诚实标注每个结论的可靠程度。

**这一步的关键约束**：判断依据是外部可验证的信号（来源的独立性、数据的时效性、作者的利益关系），不是"读起来是否专业"的直觉。当证据不足以支撑结论时，判"证据不足"——这是合法结论，不是失职。

---

## 权威性随问题变化

同一个来源在不同问题上的可信程度不一样。NEJM 上的一篇临床综述：
- 用来回答"这种药对心血管有没有影响"→ 高权威
- 用来回答"这个药的市场份额有多大"→ 中等权威，需要额外的商业数据交叉验证

评估证据时，先问"这条来源对**我正在回答的这个具体问题**有多权威"，不是给来源贴一个固定的质量标签。

具体的来源分级判据 → 详见 `source-authority.md`。Phase 2 子 Agent 已经对每条来源标注了层级（T1-T5），Phase 3 在此基础上做进一步分析。

## 回声室检测

**目标**：数出支撑每个结论的"真正独立的来源"有几个。

### 怎么判断两条信息是否独立

以下任何一种关系成立，两条信息就不算独立：

| 信号 | 判断方法 | 常见场景 |
|------|---------|---------|
| 直接引用 | A 明确引用了 B（DOI、URL、署名）| 一篇综述引用了一项研究 |
| 文本高度重叠 | 整句或整段的意思和句式结构高度相似 | PR 通稿被多家媒体原文转载 |
| 同一通稿 | 多家媒体同时发布几乎相同的内容，没有独立记者署名 | 企业新闻稿同步分发 |
| 作者重叠 | 多篇"不同"文章的作者团队大部分相同 | 同一实验室的多篇论文 |
| 机构重叠 | 同一机构的不同部门说同一件事 | 某公司不同高管在不同场合说法一致 |
| 共同引用上游 | 两篇文章引用了大量相同的参考文献 | 两篇综述都在转述同一批原始研究 |

注意区分"引用了相同的背景文献"和"依赖相同的核心证据"。两篇综述都引用了同一批基础研究，不代表它们不独立——如果分析角度、纳入标准、得出的结论不同，仍然算独立来源。合并的标准是"核心证据链相同"，不是"参考文献有交集"。

### 三步操作

1. 列出所有支撑某结论的来源
2. 按上表检查每对来源之间的关系，合并不独立的来源
3. 合并后剩下的组数 = 真正的独立来源数

**报告中使用"N 个独立来源支持"时，N 是合并后的数字，不是原始来源数。**

### 当发现回声室

如果发现"看似 10 篇文章支持"实际只有 2 个独立来源——在报告中明确指出，而不是悄悄用 2 替换 10。用户需要知道证据的广度比表面看起来窄。

## 矛盾处理

来源之间出现矛盾时，先判断矛盾的性质，再选处理方式。不是所有矛盾都需要裁决出赢家。

| 矛盾类型 | 特征 | 处理 |
|---------|------|------|
| **时间差异** | 两条数据来自不同时间点 | 以更新的为准，保留旧数据作为时间线参考。标注"截至 [日期] 的数据显示 X；而 [更早日期] 的数据显示 Y" |
| **口径差异** | 两条数据用不同标准或定义衡量同一件事 | 两个都保留，不挑一个。说明"按 [标准 A] 衡量是 X；按 [标准 B] 衡量是 Y。差异在于 [具体定义不同]" |
| **方法差异** | 两个研究用不同方法得出不同结论 | 分别描述方法和结论。如果能判断哪种方法更适合用户的场景，给出倾向性建议并说明理由 |
| **立场差异** | 不同利益方基于各自立场给出不同说法 | 标注每方的利益关系，呈现双方观点。如果某方有独立证据支撑而另一方只有立场声明，指出这个差异 |
| **真伪差异** | 有一方的信息是错误的 | **唯一需要裁决的类型。** 用证据链说明判断依据。无法确定谁对谁错时，升级为"未裁决的争议" |
| **无法分类** | 矛盾不属于以上任何类型，或在前 5 种之间犹豫不决 | 如实呈现双方说法，标注"这两条信息存在矛盾，目前无法确定原因"。错误地套用一个确定的处理方式比承认不确定更危险——犹豫时选这一项 |

**YMYL 话题中的矛盾处理更保守**：呈现双方数据和证据级别，不做倾向性选择，让用户自行判断或咨询专业人士。不在 YMYL 话题中"裁决"有争议的科学或医学问题。

## 置信度评估

不是每个结论都需要做完整的置信度评估。按重要性分级：**核心结论**（直接回答用户主问题的）做完整的双轴评估；**支撑性结论**（为核心结论提供背景或细节的）只需标注证据确定性等级和独立来源数；**事实性陈述**（已被广泛验证的背景信息）不需要单独评估。

对需要评估的结论，独立评估两个维度。这两个维度是正交的——它们衡量不同的东西，必须分开评估、分开呈现。

### 维度一：证据确定性（这些证据有多扎实）

评估的是支撑结论的证据本身的质量和充分程度，与结论内容无关。改编自 GRADE 方法（医学界 20 年实践的证据分级体系）。

| 等级 | 含义 | 典型情况 |
|------|------|---------|
| 高 | 进一步研究不太可能改变这个结论 | 多个独立高质量来源一致支持 |
| 中 | 进一步研究可能改变结论的幅度 | 有支持证据但来源有限或质量参差 |
| 低 | 进一步研究很可能改变结论 | 少量来源，或来源质量有明显局限 |
| 极低 | 对结论几乎没有把握 | 无直接证据，主要靠推断 |

**调整因素**（在初始判断基础上上调或下调）：

| 条件 | 调整 |
|------|------|
| 独立来源 ≥ 3 个 | 上调一级 |
| 独立来源 ≤ 1 个 | 下调一级 |
| 最新证据超过该领域的典型更新周期（AI/加密货币等快速变化领域：1-2 年；法律/历史等稳定领域：可放宽至 10 年以上；不确定时以 5 年为默认）| 下调一级 |
| 存在未解决的矛盾 | 下调一级 |
| 所有来源都有同方向的利益冲突 | 下调一级 |

### 维度二：结论可能性（结论成立的可能性）

基于现有证据，这个结论成立的可能性有多大。改编自 IPCC 方法（政府间气候变化专门委员会用于评估气候科学不确定性的框架）。

| 用语 | 含义 |
|------|------|
| 几乎确定 | 证据高度一致且充分 |
| 很可能 | 大部分证据支持，少量不确定性 |
| 可能 | 证据倾向支持但不够充分 |
| 大约一半 | 证据正反参半 |
| 不太可能 | 证据倾向不支持 |
| 很不可能 | 大部分证据反对 |
| 几乎不可能 | 证据高度一致地反对 |

### 两个维度的独立性

可以出现"证据确定性高但结论可能性低"的情况——比如大量高质量研究一致表明某种治疗无效。反过来也可以——仅有的少量证据全部指向同一方向，但因为来源太少，确定性只能评"低"。

### 措辞规则

以下措辞规则来自 Santesso 2020 的实证研究（190 人样本，测试不同表述方式的公众接受度）：

**用"证据表明 X"，不用"我们认为 X"。** 把判断的主体归给证据本身，而不是归给报告。原因：当结论有不确定性时，"证据对 X 不确定"的表述有 80% 的接受度，而"我们对 X 不确定"只有 37%——后者让读者觉得是分析者能力不足。

**同时提供文字描述和数值范围。** 来自 Budescu 2009 和 2014 两项独立实证研究（以及 van der Bles 2019 的验证）：只给文字（"很可能"）或只给数值（">66%"）都会导致不同读者产生不同理解。文字 + 数值双重呈现能把误读率降到最低。

**"弱推荐"必须解释原因。** 中文语境中"弱推荐"容易被误读为"证据质量差"或"观点不坚定"。实际含义是"证据确定性较低，推荐强度相应降低"——用括注说明。

### 在报告中怎么展示

**普通话题**：对关键结论标注证据确定性等级和独立来源数。

> 这一结论的证据确定性为"中"，基于 3 个独立来源 [1][4][7]。

**YMYL 话题或高严谨度要求**：同时标注两个维度。

> 证据确定性：低（仅 1 项观察性研究）。结论可能性：可能（证据方向一致但样本量有限）。

### YMYL 硬地板

证据确定性为"低"或"极低"时 → **不给出行动建议**，显式标注证据不足。不能因为用户催促、因为"总得说点什么"、因为你有直觉判断，就降低这个门槛。

如果用户明确要求在证据不足时仍提供分析，可以提供分析——但必须在结论前置显著的警告，说明证据确定性等级、具体缺什么证据、分析的局限是什么。给的是分析，不是行动建议——这条界限不可跨越。详见 `ymyl-protocol.md`。

## 负结论与弃权

"搜了但没找到"是一个合法的、有价值的结论。不要为了填满报告而降低标准引用低质量来源，也不要假装没搜过就跳过。

### 三种情况的处理

| 情况 | 处理 |
|------|------|
| **搜了，真的没有证据** | 报告中明确写出搜索了什么、在哪些数据库和来源中搜的、用了什么查询词，以及结果为空。"在 [来源列表] 中以 [查询策略] 搜索 [主题]，未找到直接证据。这一空白本身可能说明 [合理推断]。" |
| **有证据，但质量全部太差** | 列出找到的来源和它们各自的质量问题。给出"基于现有证据无法形成可靠结论"的判断，而不是硬从低质量来源里挤出一个结论。 |
| **证据相互矛盾，无法裁决** | 呈现矛盾双方，标注各自的证据质量和利益关系。明确标注"现有证据无法确定"。 |

### 弃权不是失败

报告的价值在于缩小用户的不确定性范围，不在于给出确定的答案。"这个问题目前没有可靠答案，需要通过 [专业咨询/自主调研/等待更多数据] 获取"——这本身就是有价值的缩小。用户不用再花时间搜索了，可以直接转向下一步行动。

## 自我偏差意识

你在做证据分析时，自身携带可预测的偏差。以下不是假设，是有实证数据的已知问题：

**偏好主流来源**：你倾向给"看起来专业""读起来流畅"的文本打高分，这是训练数据的分布造成的。结果是：英语来源、主流机构、学术写作风格的内容系统性地被高估。少数派观点、非英语来源、非学术但有价值的实践者经验被低估。

**"多次检查一致"不等于正确**：你反复检查同一条证据得到相同结论，这说明你的推理过程是确定性的，不说明结论是正确的。外部可验证的信号（来源的 DOI 是否可解析、作者是否可查、数据是否可获取）才是判断依据。

**强先验域名的风险**：对 Nature、NEJM、新华社、Stanford 等品牌，你倾向默认它们是可信的。但 Nature 发表过后来被撤回的重大论文（Tessier-Lavigne 事件），Harvard 有过数据造假丑闻（Gino 事件），Forbes 的编辑内容和付费专栏混在同一个域名下。**不要用"来源是 [知名机构]，因此结论可信"作为独立论据**——必须同时引用具体的外部可验证信号。

以上是最常见的三种，不是全部。在分析过程中保持对自身推理过程的警觉——尤其注意你是否在找到支持性证据后就降低了搜索强度（确认偏差），或者第一条分析的证据是否过度影响了你对后续证据的解读（锚定偏差）。

**操作要求**：对每个关键结论，问自己三个问题：

1. 我给这条来源高权威，理由里有没有"它来自知名机构"这一条？如果有，换成具体的外部信号。
2. 我搜过这个结论的反面证据吗？如果没有，现在搜。
3. 我给这条来源的评价，会不会因为它是中文/英文而系统性地偏高或偏低？

## 完备性自检

进入报告生成（Phase 4）之前，逐项检查。

### 角度覆盖

以下维度不是每个研究都要全部检查。根据研究问题的性质，跳过明显不适用的维度——比如纯技术实现对比不需要检查地域覆盖，纯中文政策问题不需要检查英文来源。对跳过的维度，在自检记录中注明"不适用：[原因]"。

| 检查项 | 问自己 |
|--------|--------|
| 每个子问题 | 有回答（包括"未找到充分证据"）？ |
| 反面证据 | 对主要结论，搜索过反对意见或反例？ |
| 少数派观点 | 只看了主流观点？有没有有价值的少数派视角被忽略？ |
| 语言覆盖 | 只搜了一种语言？中文和英文来源都查了？ |
| 时间覆盖 | 只看了最近的？历史演变是否重要？ |
| 地域覆盖 | 只看了一个地区？其他地区的情况是否不同？ |

### 证据强度

| 检查项 | 标准 |
|--------|------|
| 关键结论 | 至少 2 个独立来源支撑 |
| 有争议的结论 | 正反双方都有来源呈现 |
| 定量声明 | 数字可追溯到一手来源 |
| 因果声明 | 区分了"相关"和"因果"——不要把相关性说成因果性 |

### 反面证据的可审计性

对"搜索过反面证据"这一项——在报告中写出你搜索了什么反面查询、得到了什么结果。让用户能验证你确实做了，而不是只勾了个复选框。

### 概念创新与论证一致性

前面三个维度（角度覆盖 / 证据强度 / 反面证据可审计）查的是**证据基础**，这一节查的是**研究产出了什么洞察**——证据扎实是入场券、有真见解才是 deep research 区别于 wiki 拼接的地方。

**破立检查（P6 立新框架）**：

| 问自己 | 标准 |
|---|---|
| 本研究破了用户进研究前抱有的哪个旧概念？ | 至少能命名 1 个旧概念。一个都说不出来、研究价值就只剩"信息搬运" |
| 替代旧概念的新概念叫什么？ | 用 **4 字以内**的标签命名。命不出名说明新概念还没成形 |
| 新概念在 phase 4 报告里出现的位置？ | 至少出现在核心结论或主线复述与回扣段、不能只埋在详细分析中段 |

**为什么强制 4 字以内**：长名读者记不住、记不住就无法被带走。"轨道分离" 比 "新闻报道与意见评论的来源轨道独立判定原则" 好用 100 倍——后者是定义、前者是标签、读者向别人转述时只能用标签。

**例外**：纯事实查询（"X 公司 2025 年营收多少"）不强制破立。但纯事实查询通常用不着 deep research、走到 phase 3 自检还判定为纯事实型、先回头确认 phase 1 的研究类型判断是否准确。

**洞察一致性检查（P9 论证骨架不能违反）**：

| 问自己 | 标准 |
|---|---|
| 本研究最尖锐的洞察是哪一句？ | 能精确指出来——否则可能根本没出现尖锐洞察 |
| 这条洞察出现之后、后续证据呈现有没有违反它？ | 没违反。不能"先说 X 已死、后又花一段说 X 还有未来" |
| 这条洞察和 phase 4「关键假设与翻盘条件」段是否一致？ | 一致。洞察站在的假设、翻盘条件应能列出来；翻盘条件成立时洞察应反转 |

**典型违反**：

- 核心结论说"模型 A 显著优于 B"、详细分析里中性描述 B 的优势——读者读完不知道作者站哪边
- 主线说"行业进入存量博弈"、分析里大谈某新赛道的增量空间——洞察被自己的论证拆台

**怎么修**：不是删掉一边、是重新校准洞察的边界。例：把"模型 A 显著优于 B"改成"在场景 X 下 A 优于 B、在场景 Y 下两者持平"——洞察更精准、论证也不再矛盾。

### 未通过项的处理

- 可以补充搜索的 → 补搜后重新检查（补搜直到该项通过检查或确认无更多来源可查）
- 确实搜不到的 → 在报告的"待补研究"节中明确列出
- **不要为了通过检查清单而降低标准引用低质量来源**——具体来说：如果一条来源在来源分级中低于 T3（详见 `source-authority.md`），且是该结论的唯一支撑，不要用它来支持结论，改为在负结论中报告证据不足

## report_thesis.json 输出契约（硬约束）

phase 3 完成时、必须把整份研究的"主线判断"以结构化形式写入 `report_thesis.json`、供 phase 4 写报告时按字段调用——这是 P2 主线显式化的硬路径防御。phase 3 的整套证据分析浓缩成 6 个字段、phase 4 必须按 thesis 组织报告骨架、不允许临场重构主线（临场重构 = 让 phase 4 LLM 重新做一遍判断、判断质量不稳定）。

### 文件位置与命名

文件名：`{主题关键词}-{YYYY-MM}.report_thesis.json`（与报告同名、后缀 `.report_thesis.json`）。位置：`REPORTS_DIR`（即本 skill 目录下的 `reports/` 子目录，详见 SKILL.md「路径约定」段）。

### 6 字段 schema

| 字段 | 类型 | 说明 |
|---|---|---|
| `punchline` | string | 一句话主线（建议 30 字以内）。整份研究的核心判断、phase 4 必须把这句话**原文**至少出现在「核心结论」开头 + 「主线复述与回扣」段两处 |
| `key_judgments` | array of string | 3-5 条关键判断、每条带显式排序词（"最关键变量"、"最被低估的"、"最有可能翻盘的"等）。少于 3 条说明判断不足、多于 5 条说明没合并 |
| `key_assumptions` | array of string | 主线判断站在的 3-5 个核心假设。phase 4「关键假设与翻盘条件」段按这些假设逐条展开 |
| `thesis_chain` | array of string | 主线的因果推理链、每条一句话、按"现状 → 问题 → 为什么 → 对策"或类似逻辑组织。`["AI 编程工具市场 2024 年 70 亿、2026 年 220 亿（3 倍）", "增长不来自工具增量、来自单工具占比扩张", "Cursor 占 30%+ 已形成网络效应", "切换工具的迁移成本 > 短期效率收益", "对你的团队、应该选 Cursor 而非 Copilot"]` |
| `decision_action` | string | 用户应该执行的**具体动作**、来自 `user_profile.json` 的 `decision_context` 字段、phase 3 基于研究结论给出明确推荐。例："建议你的团队 30 天内启动从 Copilot 到 Cursor 的迁移、优先迁移 5-7 人小组试点 14 天" |
| `fallback_pivot` | string | 主线最可能错在哪、读者应该监控什么信号。例："如果 Anthropic 在 2026 Q3 发布独立 IDE、Cursor 的网络效应可能被绕开、届时重新评估" |

### 字段填写纪律

- `punchline` 必须是**一句话**——多句压缩不进去说明判断没收敛、回去合并
- `key_judgments` 每条都要有显式排序词（最 / 优先 / 关键 / 应该 / 建议）——参见 phase 4「显式排序判断」节
- `key_assumptions` 必须可证伪——"X 趋势会持续"不可证伪、"X 趋势在未来 12 个月内增速 ≥ 20%"可证伪
- `thesis_chain` 每条都是上一条的**因果延续**、不允许跳跃——能形成"现状→问题→为什么→对策"的连贯叙事
- `decision_action` 必须**具体到可执行的动作 + 时间窗口 + 验证条件**——例 "30 天内启动迁移" + "5-7 人小组试点 14 天" 这种、不能写"应该考虑使用 Cursor"
- `fallback_pivot` 必须指向**可监控的外部信号**——例 "Anthropic 发布 IDE" 而不是"如果情况变化"

### phase 4 调用契约

phase 4 写报告时 hard call 这个文件、按以下规则使用各字段：

| 字段 | phase 4 怎么用 |
|---|---|
| `punchline` | 必须**原文出现**在「核心结论」开头 + 「主线复述与回扣」段两处。validate 检查 punchline 在报告中出现次数 ≥ 2 |
| `key_judgments` | 「核心结论」段按这 3-5 条逐条展开、每条带证据 + 排序词 |
| `key_assumptions` | 「关键假设与翻盘条件」段（六段结构第 2 段）按这些假设逐条展开 + 给出每条的翻盘条件 |
| `thesis_chain` | 「详细分析」段按这条因果链组织小节顺序——不允许按"市场 / 技术 / 政策"三段式平铺 |
| `decision_action` | 「主线复述与回扣」段最后一句必须接回这个动作（与 user_profile.json 的 decision_context 配合） |
| `fallback_pivot` | 「主线复述与回扣」段倒数第二句必须包含这个监控信号 |
