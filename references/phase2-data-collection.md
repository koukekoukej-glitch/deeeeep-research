# Phase 2：数据收集

**目标**：产出一批经过初步分级的原始来源——覆盖用户问题的各个子问题，横跨相关领域。

**核心原则**：搜索的广度和精度取决于派对了人。按领域分工让每个子 Agent 用自己最擅长的方法搜自己最熟悉的地方，比一个通用 Agent 搜所有地方效果好得多。

**这一步的关键约束**：你不亲自搜索。你决定这个问题涉及哪些领域、派哪些子 Agent 去搜、给每个子 Agent 什么具体任务，然后收集和汇总结果。

---

## 工具与能力边界

- **WebSearch**——通用搜索，适合发现来源和获取广泛信息
- **WebFetch**——读取特定 URL 的内容，适合深入阅读已发现的来源
- **已知限制**：无法访问付费数据库（如付费学术期刊全文、Gartner 付费报告）。遇到付费墙时，尝试找公开摘要、预印本版本或替代来源

---

## 第一步：判断需要哪些领域

根据 Phase 1 拆出的子问题，判断每个子问题属于哪个领域。六个专业领域覆盖了绝大多数研究场景：

| 领域 | 覆盖什么 | 何时启用 |
|------|---------|---------|
| 英文学术 | 科学证据、临床研究、理论分析、学术综述 | 子问题需要学术论文或研究数据支撑 |
| 中文学术 | 中文期刊、中文学术生态、中国临床试验 | 子问题涉及中国学术研究或中文文献 |
| 英文工程 | 技术文档、开源项目、RFC 标准、技术社区 | 子问题涉及技术实现、框架选型、代码 |
| 中文工程 | 国标/行标、国内大厂技术博客、中文技术社区 | 子问题涉及国内技术生态或中文技术资料 |
| 英文商业 | SEC 监管文件、行业报告、财经媒体、事实核查 | 子问题涉及市场、商业模式、财务数据 |
| 中文商业 | A 股/港股披露、央媒政策、中文财经媒体 | 子问题涉及中国市场、政策、中文商业信息 |

**一个子问题可以同时派给多个领域。** 比如"X 药的安全性"同时需要英文学术（临床数据）和中文学术（中国临床试验）。

### 六个领域覆盖不到时怎么办

大多数问题都能被这六个领域覆盖——医疗走学术 + YMYL 标记，法律走商业 + YMYL 标记，政策走中文商业 + YMYL 标记。但有两种情况需要特殊处理：

| 情况 | 处理方式 |
|------|---------|
| 需要社区/用户声音（产品体验、用户痛点、市场口碑） | 在对应领域的子代理 prompt 里额外指定搜索 Reddit / 知乎 / HackerNews。社区数据不需要独立的子代理，但要明确告诉子代理：社区来源只能用于发现问题和假设，不能用于支撑结论。 |
| 问题完全超出六个领域（比如纯艺术鉴赏、个人情感咨询） | 告知用户："这个问题超出了我的系统化研究能力，我可以尝试搜索但无法保证覆盖度和权威性。" 用户同意后，用通用 WebSearch 直接搜索，报告中标注"未经领域专业方法论验证"。 |

## 第二步：派出子代理

用 Agent 工具为每个需要的领域 spawn 一个子代理。**在一条消息中同时发出所有 spawn 请求，让它们并行执行。**

每个子代理的 prompt 按以下结构写：

1. **读取方法论**——告诉子代理去读自己的方法论文档
2. **子问题列表**——明确说清要回答哪几个子问题
3. **YMYL 标记**——如果涉及 YMYL 话题，告知子代理采用更严格的证据标准
4. **失败重构规则**——首轮搜不到时换同义术语重试——每轮只改一个维度（换词 → 调范围 → 换语言/来源），连续两轮零结果且无新策略可试时标记为未找到
5. **输出要求**——对每条找到的信息返回：来源 URL、来源层级、关键发现摘要、利益冲突标注

**六个子代理的方法论文档：**

| 领域 | 方法论文档 |
|------|-----------|
| 英文学术 | `references/agents/en-academic.md` |
| 中文学术 | `references/agents/zh-academic.md` |
| 英文工程 | `references/agents/en-engineering.md` |
| 中文工程 | `references/agents/zh-engineering.md` |
| 英文商业 | `references/agents/en-commercial.md` |
| 中文商业 | `references/agents/zh-commercial.md` |

**子代理 prompt 示例（英文学术组）：**

"先读取 `references/agents/en-academic.md` 获取你的搜索方法论和权威判断标准。

你负责以下 2 个子问题的学术文献搜索：
1. X 技术在 Y 场景下的效果如何？有没有对照实验数据？
2. X 技术的已知局限性和失败案例有哪些？

本次研究涉及医疗健康（YMYL），请采用更严格的证据标准——优先一手权威来源，预印本结论必须交叉验证。

首轮搜不到时换同义术语重试——每轮只改一个维度（换词 → 调范围 → 换语言/来源），连续两轮零结果且无新策略可试时标记为未找到。

对每条找到的信息返回：来源 URL、来源层级（一手权威/强二手/灰色一手/聚合转述）、关键发现摘要（2-3 句）、利益冲突标注（如有）。"
</example>

## 第三步：收集结果

所有子代理返回后，汇总各自的发现：

- **跨语言发现**——同一个议题的英文源和中文源都找到了，记录下来供 Phase 3 交叉验证
- **低质量警告**——某个领域的子代理返回的结果大部分是聚合转述或更差的来源，记录"该领域未找到高质量来源"，在报告中如实说明
- **覆盖度检查**——对照 Phase 1 的子问题列表，每个子问题是否都有至少一条来源覆盖？遗漏的子问题考虑补派子代理或用通用搜索补充

---

## 预算意识

来源数量由覆盖度决定——每个子问题至少有一条可用来源覆盖，核心结论至少有两个独立来源支撑。达到这个标准就够了，不需要为凑数继续搜；没达到就继续搜，不因为"已经搜了很多"就停手。

搜索进行中发现问题比预期复杂得多 → 告知用户，让用户决定是否继续深入。每完成 2-3 个子问题的搜索后，向用户简要汇报当前进展和初步发现方向。

完成 Phase 2 后 → 读取 `references/phase3-evidence-analysis.md` 开始证据分析。
